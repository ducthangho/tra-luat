WP1030: the package secret scanner (`pkg_secret_scan`, dev-side, not in the release) no longer skips
files whose suffix is not in `TEXT_SUFFIXES`. Such files (`.log`, `.patch`, `.csv`, ...) now take the
same path as files without a suffix: they are scanned unless they exceed `MAX_BYTES` or carry a NUL byte
in the first 8192 bytes. The default is to scan; a file is skipped only for a measured property, never
for its name. Before the fix a key planted in `a.log`, `b.patch` and `c.csv` was missed and only the
`d.txt` control was reported. Fragment `wp1030_pkg_secret_scan_duoi_la` runs the real scanner on a temp
fixture (key built at runtime): the hit set must equal the four text-like files, line 2,
`google_oauth_client_secret`; a NUL-led `.dat` and an oversized `.log` stay silent; a suffix-less
`credentials` is still a hit and the scanner's own name is still skipped. In an unpacked release (no
scanner, no `.git`, release policy excluding the scanner on a real sentinel file) it prints one `BỎ QUA`
line; a checkout with `.git` but no scanner fails. Measured: on the current release bundle and on the
whole repository tree the new scanner adds no hit over the old one. Not measured: `TEXT_SUFFIXES` files
still have no size cap (out of scope), encoded or binary-embedded secrets, and whether any earlier
Package upload carried an odd-suffix secret.
