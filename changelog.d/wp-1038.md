WP1038 (CLOUD-SETUP-P2A-EXEC): new `tl agent-creds-exec [--claude] [--gemini] -- <command> …` runs one command with the
Claude token (`CLAUDE_CODE_OAUTH_TOKEN`) and/or the Gemini key (`GEMINI_API_KEY`) from `tl_agent_creds.enc` set only in
that child's environment. The file is downloaded on every call and decrypted in memory with `TL_MASTER_KEY`; nothing is
exported to the session, written to disk or cached. A failed download, a missing or wrong master key, `schema` other
than 1, or a missing or empty requested key returns rc 4 without starting the child. No flag or no command after `--`
returns rc 2 before any download. The command name is resolved with `shutil.which` (rc 127 when not found), the child
runs from an argv list without a shell, and its exit code is returned as is. No branch prints a credential value.
A `schema` that is JSON `true` is refused too (it compares equal to 1 in Python). `AGENT_CREDS_FILEID` now holds the real file id. The top-level `tl` parser no longer accepts abbreviated global flags (`--det`, `--tim`): the PreToolUse guard does not know those spellings and treated them as taking a value, which hid the command name from it. The command needs no webapp config, the PreToolUse guard blocks it for
subagents, and the command-registry ratchet and goldens count it. New `r1000_*` cases.
