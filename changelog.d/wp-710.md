WP710: Add a bounded Windows NLM credential refresh and opt-in keepalive with a
real notebook canary, serialized stage, machine-readable failures, and offline
behavioral tests. `nlm-auth-stage`, `secrets-set --nlm` and `secrets-stage` share
one gate: they upload NLM credentials only after a live canary whose raw JSON
answer is exactly one notebook object (every id key equal to the expected id,
every title/name key a non-blank string, no duplicate or case-variant keys, no
`ok:false`/`error`), and read the credential jar only after that canary;
`--force` cannot bypass it, and the wrapper applies the same allow-list. A
payload guard sends `nlm_auth` in a bundle only when it is the jar that just
passed the canary: `secrets-set` without `--nlm` on a bundle that carries
`nlm_auth` is refused (rc 4), `secrets-stage` without a jar stops (rc 3), and
`--no-nlm` removes `nlm_auth` from the packed config. The three commands print
only fixed canary codes and exception class names; an exception mid-command
returns rc 5 instead of a traceback (rc 5 does not prove nothing was uploaded).
The canary notebook is pinned by `TL_CANARY_NOTEBOOK_ID`, which a profile config
cannot overwrite. The wrapper marks every child with `TRA_LUAT_NLM_OP`; on Linux
it stops and confirms the whole marked tree on timeout and before the next
step, and a new lock owner waits for any marked process. On Windows only a
descendant that still holds the pipes is detected (not measured natively).
`stage_failure` means the stage command was called and may have uploaded.
