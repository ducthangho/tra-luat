WP727: `_refresh_nlm_auth` (behind `nlm-auth-stage --refresh`) now runs `nlm auth refresh`, the command
the WP710 wrapper uses, instead of `nlm login --check`, which only checks and reports green on a dead
session. It is best-effort and bounded (120 s), prints nothing, and its rc is not evidence: the canary
gate still runs afterwards and alone decides the upload. On timeout only the direct child is killed, so
`nlm-auth-stage`, `secrets-stage` and `secrets-set` stop (rc 2). Hints in `scripts/tl_gws.py` print the
runnable WP710 wrapper call or `tl nlm-auth-status` instead of `nlm login --check` or a bare stage after
`nlm login`. Fragment `wp727_tl_gws_refresh` checks argv/timeout, error containment, the timeout stop,
0 uploads on a False/None canary (rc 4, with `--refresh --force`), a static allowlist of `login --check`
lines and strings, and runs every edited hint branch offline: the real message must reach its branch,
carry no `login --check` hint and not leak cookie content. Not measured: real `nlm auth refresh` (LIVE).
