WP802: `launcher.py doctor` no longer stays green when the bare-name `rg` or `git` (the first copy on PATH, the one an
agent types in a shell) is broken while a later copy runs. Measured 17-10 on Linux: broken `rg` first on PATH gave
`doctor` rc=0 with `co: True` pointing at the good copy, while `rg --version` failed. Such a tool now gets
`trang_thai: BI_CHE` with both paths and a fix (reorder PATH or remove the broken copy), counts as missing a required
tool, and `doctor` exits 12; `co` stays true because the tool is installed. Scope is only `rg` and `git`: `bash` (WSL
first on Windows PATH) and `python` (three names) are excluded. The Windows `rg` install recipe is now
`winget … || choco …` in `ops/cong_cu.yaml` and in the `doctor` hint; the YAML falls back to the WinGet Links folder
when the current shell cannot see the new shim, and appends that folder to `$GITHUB_PATH` when set, because later
runner steps start a fresh shell (measured: launcher-windows run 39093706610, install `DAT` then next step could not
find `rg`). `session-start.sh` no longer tries `apt-get`/`cargo` on Windows (Git
Bash): it prints a warning plus that one command and leaves the block to `doctor`. On Linux the `cargo` fallback now
checks `co_chay rg` instead of `co rg`, so a present-but-broken `rg` still reaches `cargo`. Seven new cases
(`r802_*`) cover N1–N8 of `ops/specs/wp802.md`, including a 0-byte `rg.exe` first on PATH on Windows and a check
that the three install tables match. Nine mutations (six on `launcher.py`, three on the hook through a new
`DOT_BIEN_HOOK` table run on temp copies) each kill their target case through its own assertion. `t106` now expects `BI_CHE` and exit 12 for its broken-first
`rg` (spec Q2), while still checking the fallback to the good copy and the probe order.
