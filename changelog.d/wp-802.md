WP802: `launcher.py doctor` now resolves `rg`/`git` the way the shell does (PATH order, an empty entry is the current
directory) and probes that copy first. If it is broken while another copy runs, the tool gets `trang_thai: BI_CHE`
with both paths and a fix, counts as missing a required tool, and `doctor` exits 12 (`co` stays true). Before, a
broken first copy was skipped and `doctor` exited 0. `bash`/`python` are out of scope. The Windows `rg` recipe is now
`winget … || choco …` in `ops/cong_cu.yaml`, the `doctor` hint and the hook; the YAML prints the first folder whose
`rg` actually runs and appends it to `$GITHUB_PATH` when set (later runner steps start a fresh shell). On Windows
`session-start.sh` no longer runs installers: it prints that command and leaves the block to `doctor`; on Linux the
`cargo` fallback checks `co_chay rg`. New `r802_*` cases and `wp802_*` mutations (a `DOT_BIEN_HOOK` table also
mutates the hook and `ops/cong_cu.yaml` on temp copies); `t106` now expects `BI_CHE` per spec Q2.
