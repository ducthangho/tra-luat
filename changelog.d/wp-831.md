WP831: the Linux and macOS `rg` recipes in `ops/cong_cu.yaml` now pick their folder the same way the Windows one
does. After `apt-get`/`brew` they print the first folder whose `rg` passes `ops/cong_cu.py kiem-tra --chi rg`, and
append it to `$GITHUB_PATH` when that is set. Linux tries the folder `dpkg -L ripgrep` reports (`/usr/bin` when that
cannot be read), then `command -v rg`. macOS tries `$(brew --prefix)/bin`, then `command -v rg`. Before, both printed
`dirname "$(command -v rg)"`, so a broken `rg` earlier in PATH was the folder handed back. When no candidate passes,
the install now fails instead of handing back a folder. `docs/GOI_AGENT_DA_NEN.md` now lists the required tools per
platform, as `_bat_buoc` in `launcher.py` resolves them, and says that exit 12 also covers `BI_CHE` (the bare-name
`rg`/`git` is broken while another copy runs). New `r831_*` cases and `wp831_*` YAML mutations. The `wp802` Windows
anchor is longer so that it still matches exactly once.
