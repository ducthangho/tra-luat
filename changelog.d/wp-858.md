WP858: the twelve `git`, `python`, `shellcheck` and `bash` recipes in `ops/cong_cu.yaml` now call a new
`chon_thu_muc_chay_duoc` in `ops/cai_cong_cu.sh` instead of printing `dirname "$(command -v <tool>)"`, which handed
back a broken copy earlier in PATH. It prints the first candidate folder (Linux `/usr/bin`, macOS `$(brew --prefix)/bin`,
Windows the choco install folders, then `command -v`) that makes `cong_cu.py kiem-tra --chi <tool>` pass when put
first in PATH. No passing candidate, a failing `cygpath` or a failed write to `$GITHUB_PATH` fails the install. If
the bare name already passes, PATH is left alone and the last line is `/dev/null`, never a folder: re-printing that
folder brought a broken `rg` from it back to the front under `--bat-buoc`. Known limit (owner, #858): `cong_cu.py`
checks `python` with `sys.executable`, so a broken `python` first in PATH is still not caught.

`/tmp/.git`, and the credential store rightly refused every home under `/tmp`, so `t86` failed when a Codex run
overlapped the suite. The `edit_skill_assert_count_gate_dry` selftest uses its own `mkdtemp` folder, not a fixed
name, so parallel selftests no longer clash. New `r858_*` cases and `wp858_*` mutations, each also killed by a
pure-Python case so it counts on Windows; the mutation runner can target `ops/cai_cong_cu.sh` and the selftest.
