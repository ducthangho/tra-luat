WP886: `ops/cong_cu.py` now checks the `python` the shell would actually run. A probe whose command starts with
`python` (the `python` tool, PyYAML, jsonschema) used to run with `sys.executable`, so a broken `python` at the front
of PATH still passed. It now resolves the bare name from PATH in the same order as `ops/cai_cong_cu.sh`: `python`,
then `python3`, then `py -3`. On Windows only names with a PATHEXT extension count, like other native processes.
A machine with only `python3` still passes, and module probes measure that interpreter. When none of the three names
is on PATH the result is `KHONG_DO_DUOC` and the detail lists the missing names. New `r886_*` cases and `wp886_*`
mutations; the #858 python case is back to the full N1/N3 checks, closing debt `python-probe-khong-theo-PATH`.
The `ops/cong_cu_test.py` python3-only fixture now creates `python3.cmd` on Windows, since an extensionless
`python3` is not a name native processes resolve.
