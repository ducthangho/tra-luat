# Ephemeral session credentials

Use `.claude/dev/session_credentials.py`; it reports only state and never a secret.

* `CODEX_HOME` is authoritative. If absent, every helper uses `~/.codex`. `codex-destination-check` validates it before the session hook invokes Codex at all; an already-readable login does not bypass the check. A refusal exports `TRA_LUAT_CODEX_BLOCKED=1`, which every launcher Codex path honors, including `launcher.py run -- codex …`, version, live-auth, prepare, and final doctor probes. Generic `run` resolves and binds executable identity once, including PATH entries, absolute paths, Windows `.exe`/`.cmd`/`.bat`/`.com` shims, renamed symlink/reparse aliases, and same-file hard links. A path-bearing relative argv0 is resolved against the declared workspace **before** any PATH lookup; only a bare command name uses PATH/PATHEXT. The bound target and provider identity are then reused unchanged by the Codex refusal, transport record, capability probe, and final spawn; an unresolvable or ambiguous identity fails before any child. Provider runs also receive the same provider-scoped credential allowlist and sanitized PATH as doctor/session children; unrelated ambient credentials are not inherited, while generic non-provider commands retain their existing environment contract. Materialization is rejected before decoding or writing when the effective `auth.json` resolves inside the repository, including through a symlinked parent.
* Every secret write uses an **actual opened parent capability**. On POSIX the writer starts from an opened trusted root and opens each existing component or creates each missing component relative to the directory capability already held; it never runs pathname `mkdir` and reopens the result. The helper validates the opened ancestry, then performs create, mode change, sync, target inspection, replace, cleanup, and final verification relative to the same capability. For the shared session credential writer, immediately after `O_CREAT|O_EXCL` it records the created inode identity before chmod, write, flush, or fsync. If any later shared-writer operation fails—including every parent-directory fsync error such as `EINVAL`, `ENOTSUP`, or `EIO` after replace—it removes only an entry that still has that exact identity; a different-inode replacement is preserved, the original exception remains authoritative, and no partial or complete credential is reported as a failed write. Exceptional unwind attempts every descriptor close without letting unlink/close failures replace the first write/durability exception; with no earlier exception, a close failure is fatal rather than a reported success. It never falls back to a pathname after validation, so substituting a missing component with a symlink fails before secret bytes are written. This guarantee prevents a pathname alias swap from substituting a different directory. It does not claim to defeat a concurrent actor with permission to reparent the already-open directory object itself after validation: the capability remains bound to that same inode, so moving it under a repository moves the subsequent write there too. Environments that include that stronger attacker need OS namespace/permission confinement. POSIX supplies the required primitives. On Windows, where this runtime does not expose equivalent handle-relative primitives, the operation fails closed before child launch or write and reports `not_measured`.
* Capture a Claude Pro/Max subscription token with `python3 .claude/dev/session_credentials.py claude-capture --output /tmp/claude.token`. The output must resolve outside the repository. The helper checks that boundary before starting `claude setup-token`, suppresses its token-bearing output, and atomically writes mode `0600`. Claude capture/probe, GitHub probe, and Codex device-auth/live-check all receive the same kind of process-created private provider hierarchy. `HOME`, every XDG root, and all three temp variables (`TMPDIR`, `TMP`, `TEMP`) are rebound beneath it; ambient temp variables never choose or reach provider storage, and only that provider's credential is added. A Codex live check first guards and capability-reads the canonical `CODEX_HOME/auth.json`; repository or parent-link refusal starts zero provider contexts and zero children. Its closed result is `passed`, `rejected`, or `not_measured`: only evidence-backed credential/model refusal (or a policy refusal) is `rejected`; missing CLI, timeout, unexplained local failure, provider allocation, and provider cleanup failure are `not_measured`. The ordinary credential directory is used only as `CODEX_HOME`; it may contain only `auth.json` and never needs the private `HOME`/XDG/temp scaffold, which comes from a separate disposable hierarchy. Allocation starts from `/tmp` on POSIX or the Windows Shell LocalAppData temp directory, not environment-derived temp state. On exit, cleanup quarantines and rechecks the exact allocated root identity, checks recursive deletion and absence, and refuses a swapped link/junction/reparse point without following it. A deletion exception or residual root prevents `passed` and reports `not_measured`. This does not claim to defeat a concurrent actor running as the same OS principal who can reparent provider storage while the child is using it; that stronger runtime threat model requires OS namespace or principal isolation.
* Claude capture/probe and GitHub probe bind their provider executable **before reading a token or token file**. Discovery uses only raw entries from the supplied `PATH` that are already absolute, rejects empty/relative/tilde-relative entries without expanding `~` or consulting ambient `HOME`, rejects the repository and process-trusted temporary hierarchy, and requires exactly one candidate. POSIX accepts an executable or a symlink alias whose resolved target is a regular executable; a shebang is parsed into a bound absolute interpreter, including a uniquely resolved `#!/usr/bin/env node`, and the kernel is never allowed to perform an unbound interpreter lookup. Windows uses the closed `.com`/`.exe`/`.bat`/`.cmd` discovery set. A `.cmd` is accepted only when it is a recognized npm shim whose `node.exe` and JavaScript entry file can both be identity-bound; the helper launches those two absolute files directly. Unsupported script/shim forms fail closed. The provider and every launch-support identity are revalidated immediately before spawn, argv0 is absolute, and the child receives only the sanitized absolute `PATH`. Missing, ambiguous, untrusted, or replaced executable/support files start zero children and return `not_measured`; provider upgrades are picked up on the next independent invocation. Tokens remain absent from argv and reports.
* Set `GITHUB_PAT` in the session environment and run `python3 .claude/dev/session_credentials.py github-probe --repo ducthangho/tra-luat`. The PAT is mapped to `GH_TOKEN` only in the two `gh api` children (`user` and `repos/…`); it is absent from argv and reports.
* Keep `TL_MASTER_KEY` as the root for the existing encrypted Drive bundle. Run `python3 .claude/dev/session_credentials.py tl-bootstrap --env cowork --secrets-file /tmp/s.enc`; this rejects a direct or parent-linked repository bundle, invokes the repository's canonical `scripts/tl.py` with the repository root as its fixed working directory, and does not duplicate GAS/GWS/NLM storage or crypto. Before dispatch it canonicalizes and validates each directory candidate itself plus every ancestor for `HOME`, XDG, GWS, TL-cache, and temporary roots because the delegated child writes decrypted GAS/GWS/NLM state below them. An exact worktree root, bare-repository root, or link/junction alias is rejected before child start; permitted external roots may be nonexistent and are delegated in canonical form. The NLM/GWS secret writer applies the same component-by-component capability-relative creation rule described above. It records the `O_EXCL` inode before chmod, holds that inode open so an unlink/recreate cannot recycle its identity, and retains both temporary and final cleanup names until parent-directory fsync succeeds. Any failure from chmod through directory fsync removes only the still-matching writer inode, preserves a replacement, and re-raises the original exception. `--secrets-file` is mandatory for both `tl-bootstrap` and the combined `bootstrap`; if absent, no provider or TL child is started. The delegated exit contract is preserved: rc `0` is `passed`; rc `1` is `not_measured` with reason `degraded`; rc `2` is `not_measured` with reason `precondition`; rc `3` is `rejected` with reason `credential_or_bundle_rejected`; any other nonzero rc is `not_measured` with reason `unclassified_exit`.
* Codex device authorization always runs with the private provider `HOME` as `CODEX_HOME`; `lay` has no caller-selected home. Successful auth is copied out only through the same guarded writer. Checked cleanup failure overrides an otherwise successful acquisition and returns `not_measured`.
* NLM auth restoration accepts a closed relative schema only: `auth.json`, `profiles/default/cookies.json`, and `profiles/default/metadata.json`. Traversal, absolute paths, backslashes, extra profile paths, and non-text payloads are rejected. A link, junction, or reparse point in the supplied base or an existing lexical parent is rejected before schema planning; generated nested target parents are all checked before the first write. Resolving a link into an external non-repository directory is not accepted, while ordinary nonexistent components remain supported.
* To perform all four steps in a single deterministic report, run `python3
  .claude/dev/session_credentials.py bootstrap --env cowork --secrets-file
  /tmp/s.enc --claude-token-file /tmp/claude.token`. This materializes
  `CODEX_AUTH_JSON` under the effective `CODEX_HOME`, passes the Claude token only
  to a minimal non-interactive Claude model probe (success requires a known marker
  in model stdout), normalizes and probes GitHub, and delegates the TL step.

Every top-level and component result uses exactly one status: `missing` means the
credential was absent; `rejected` means malformed, unsafe repository destination,
or evidence-backed refusal (for Codex/Claude, a closed contextual credential/model-refusal phrase; generic local words such as `login`, `oauth`, or `authentication`, and bare numbers `401`/`403`, are not refusal evidence; for GitHub, HTTP 401/403/404 only when an `X-GitHub-*` header appears in that same response header section—body lines, proxy text, or another response block cannot supply it); `network_error` means the GitHub transport supplied independent bounded transport-failure evidence or the Claude process supplied explicit transport evidence such as connection refusal/reset or DNS failure; a GitHub CLI timeout without such evidence is `not_measured`, not `network_error`; an unknown Claude nonzero result remains `not_measured`, as does Claude rc `0` when the probe's exact standalone success marker is absent;
`not_measured` means no reliable measurement was possible (missing CLI, timeout,
local I/O failure, or inability to create or verifiably remove validated private provider storage); and
`passed` requires the relevant operation to complete.
Never paste a token into an argument, issue, log, repository file, or Git history.
Do not place `CODEX_HOME`, Claude token output, or the encrypted TL bundle under
the checkout; warnings in documentation are not a substitute for the enforced
resolved-path guard.
