## Implementation notes

**Module (`ProximaControl.psm1`)**
- **Exports:** exactly `px` and `Invoke-ProximaOperation`, both SupportsShouldProcess with ConfirmImpact Medium. No aliases or variables are exported.
- **Errors:** every error is `ProximaControl.<Code>` with a fixed message, no inner exception and a null TargetObject. S1 errors (`ProximaConfig.*`) are passed through unchanged.
- **S1 dependency:** the sibling `ProximaConfig.psm1` is hashed against the pinned `59abfa86…` before it is imported, then used only through the pinned module object. S1's private helpers run inside that module's scope: path syntax, `Open-PxChain`, `Assert-PxOutside`, `Get-PxNode`, `Test-PxChild` and the strict JSON reader.
- **Target check:** every action except `help` requires `-ConfigPath`, `-RepositoryRoot` and `-TargetId`. Each call reads the config through S1, then requires an Ordinal exact match on `targetId`, under `-WhatIf` too.
- **Fingerprint:** SHA256 over a tagged, fixed-order encoding of the six fields, each with a 4-byte big-endian length prefix. A missing field is byte 0, which keeps it distinct from an empty one. The display shows only `px target <12 hex>`.
- **Gate order:** `ShouldProcess` runs after pure validation and before any query, selection change, session, journal, process, service or network effect. `-Force` only affects the pending-record guard on stop/restart.
- **Selection:** stored as Selection[fingerprint][provider] in Ordinal dictionaries, keyed through `Get-PxcSelectionKey`.
- **Model membership:** a model id belongs to provider P only if it starts with `P/` and is advertised verbatim (both Ordinal).
- **Endpoint:** one constant `$script:EndpointBody` with a fixed set of 11 keys, checked with Ordinal comparison and real `bool`/`int` types. Effective WhatIf is ambient OR envelope, and it returns before any filesystem access. Then: path syntax, then both `.psm1` hashes, then `Import-Module` by exact path, then a call through the module object.
- **Backend:** primitives sit in a private `$script:Prim` table: NewSession, RemoveSession, InvokeRemote, Http, GetProcess, UiSessions, GetService, ServiceControl, NewId. Defaults use module-qualified commands. HTTP uses one HttpClient per request: no proxy, no redirects, no cookies, Expect-Continue off, no retry.
- **Journal:**
  - Containment outside ProtectedRoot is proven for the base before any directory is created, and each level is reopened and checked after creation.
  - The record file is created with CreateNew, then its handle is checked with S1 (links = 1, direct child of the journal directory) and held until finalisation.
  - The record says `pending` before the POST. Any non-200 or exception becomes `unknown`.
  - The pending guard blocks unless every directory entry is a GUID-named `.json` whose `state` is exactly `completed`.
- **Service:** only a quoted exact `<base>\runtime\Proxima.exe`, or the unquoted path when it has no spaces, under the exact name `ProximaGateway`. Anything else fails closed as `ServiceIdentityUnverified`.

**Wrapper (`Run-Px.ps1`)**
- Reuses a loaded `ProximaControl` only from the same path and never re-imports with `-Force`; a module from another path fails with `ModuleConflict`.
- Forwards only bound parameters, an explicit `WhatIf = [bool]$WhatIfPreference`, and `-Confirm` if bound.

**Choices you should know about**
- Any non-200 answer to the POST, including 4xx, is recorded as `unknown`. This is conservative: it blocks stop/restart until `-Force`.
- Completed records are kept; there is no housekeeping.
- The check of "all streams" in X2-07 does not include `$global:Error` history, which holds the fakes' own raw exceptions.

## How the harness works

- **Exit codes:** rc 0 when all required IDs pass and cleanup is verified; rc 1 when a case fails (an absent module gives `API_ABSENT` in every case, and every case still runs); rc 2 for setup or cleanup errors. The last stdout line is `RESULT N/T passed; …`.
- **Report schema `proxima_control_tests.v1`:**
  - `cases[]` with `{id, outcome, reason}`; `mandatory_ids`, `required_ids`, `passed`, `failed`, `failed_ids`, `setup_error_ids`
  - PowerShell version and edition, requested and measured culture plus a probe, `child_exes`
  - `children[]`: kind, exe, command, rc, output SHA, and the child's version, edition and cultures
  - Hashes of the module, wrapper, S1 and harness; best-effort `git_head`/`git_tree`
  - `primitives_replaced` (9/9 asserted before any product call), `counterexample_evidence[]`, `cleanup`
- **Fixture:** `<ScratchRoot>\pxctl-<run>`, deleted only on rc 0 by a delete that never follows junctions. The outside sentinel is `<ScratchRoot>\pxctl-keep-<run>\keep.txt`. The report path and the evidence directory are never deleted.
- **Counterexample evidence**, in `<EvidenceRoot|ScratchRoot>\pxctl-evid-<run>\`:
  - `CXnn\` holds copies of the three sources, with the mutated one
  - Beside it: `CXnn.report.json`, `CXnn.output.txt`, `CXnn.record.json` (command, rc, anchor, replacement, hashes, matched tokens, verdict)
  - Credit requires rc 1 and the named token in a failed case. The child must also report: same source hash, `api_state=present`, no setup error, clean cleanup, matching culture. rc 0 is reported as `SURVIVED` with no credit.
- **Child processes:**
  - The endpoint child replays the product's own captured handshake envelope and the exact `EndpointBody` object via CLIXML. It runs with ambient WhatIf false under this exe and, if installed, the other PowerShell edition. It covers 14 items: WhatIf, shape, protocol, hash, benign wrong code, S1 mismatch and positive handshake.
  - The fresh-process wrapper child receives its arguments through CLIXML.
  - `-TestCulture` is forwarded to every child, and each child's measured culture is checked.
- **Wire tests:** X5-01 and X5-06 use a TcpListener on an ephemeral `127.0.0.1` port in an owned runspace. Only in those cases is the real Http primitive restored; credentials are dummy.

## Remaining risks (unmeasured PowerShell behaviour I relied on)

1. **Syntax:** the files have never been parsed; a typo would cause setup or import failure.
2. **OnRemove:** assumed to fire on `Import-Module -Force` (X3-01).
3. **Scope of fake handlers:** they reach `$DefaultHttp`/`$DefaultRemote` through dynamic scope from module-invoked scriptblocks.
4. **`Remove-PSSession`:** assumed to accept `-WhatIf`/`-Confirm`. If it doesn't, the real default primitive breaks, though tests use fakes.

6. **WhatIf text:** may be localized, so the tests look only for the fingerprint prefix.
7. **HttpClient and the wire server:** PS5.1 HttpClient and Expect-Continue behaviour against the hand-rolled server is assumed, not measured.
8. **Real primitives in children:** endpoint and fresh-wrapper children use real primitives. I checked by reading that all their paths, including under each mutant, stop before any hazardous call. This should be verified statically.
9. **Pre-existing state:** the base directory must already exist for the journal and guard to work; a missing base fails closed.
