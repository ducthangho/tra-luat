## How F03 is closed
**Cause:** `Get-PxcGateway` checked that the PID in the metadata belonged to the right process, but never checked who was actually listening on the advertised port.

**Fix:** a new step in `Get-PxcGateway` (`ProximaControl.psm1:165-186`). It runs after the metadata, session-0 and runtime-path checks and before the URL is returned. Every HTTP call (status, models, use via models, ask) gets its URL only from this function, on both the local path and the exported `Invoke-ProximaOperation` that the remote endpoint runs. So the API key and the prompt can't be sent until the check passes. Any failure gives the fixed code `ProximaControl.ListenerUnverified`.

**Listener record rules:**
- **Every returned record** must have:
  - `LocalPort` as a native integer equal to the metadata port;
  - `State` and `OwningProcess` as native integers (via the new `Get-PxcInt`, which accepts byte, sbyte, int16, uint16, int, uint32, long and uint64, and rejects bool, string, float, decimal, enum and null);
  - `LocalAddress` as a string that `[Net.IPAddress]::TryParse` accepts.

  Otherwise the request is rejected.
- **Applicable records** are `State == 2` (Listen) on `127.0.0.1` or `0.0.0.0`, on `::`, or on the IPv4-mapped forms of those (`::ffff:…`).
  - Every applicable record must be owned by the validated PID.
  - At least one must be a plain IPv4 record (`127.0.0.1` or `0.0.0.0`).
- **Ignored records:** other states (for example TimeWait with owner 0), `::1`, `127.0.0.2` and other addresses. A Listen or TimeWait record that isn't applicable doesn't reject the request on its own; the request fails only if no applicable record remains.
- **Rejected:** an empty result, a denied or failed query, a null or malformed record, a port mismatch, a wrong owner, conflicting applicable owners, or a listener only on IPv6 or `::`.

**The 10th private primitive:** `GetTcpListener` runs `CimCmdlets\Get-CimInstance -Namespace ROOT/StandardCimv2 -ClassName MSFT_NetTCPConnection -Filter LocalPort=<n>` with `-ErrorAction Stop`. It only reads. There's no fallback and no public callback.

**Everything else is unchanged:** the fixed `127.0.0.1` URL, no proxy/redirect/cookies, exactly one POST with no retry, and the journal, service, session, fingerprint and WhatIf guards. WhatIf still returns before `Get-PxcGateway`, so it makes no listener query.

## Uncertainties to check before calling this fixed
1. **Two approved rules are now looser.** `Install-Fakes` now also accepts the exact pre-r4 9-key table, so old H3 can't fail only on setup. This trades against "exact count assertions never weakened". A candidate can't reach 26/26 that way, but a reviewer should judge it.
2. **Listener permissions are untested.** Whether a non-admin user, or the session-0 remote endpoint, can read MSFT_NetTCPConnection with owner PIDs is unknown. If not, every gateway call fails closed.
3. **A real Proxima listening only on dual-stack `::` would be denied** on every call. Its real listening layout is unknown.
4. **Records that aren't applicable** (other state or address) are ignored rather than rejected. Only malformed records or a port mismatch reject the request outright. Please confirm this reading of "mismatched state/address".
5. **`IPAddress.TryParse` is lenient** for IPv4 strings. This can only make more records applicable, so it errs on the strict side.
6. **Harness dynamic scope is unmeasured.** The listener handlers call the script-scope `New-ListenRec` from inside a module call. Existing handlers resolve `$DefaultHttp` the same way, but this exact path hasn't been run. The `Find-ScopeShadowing` self-check also hasn't been run on the new code.
7. **The check is a snapshot, not atomic.** An administrator or port-reuse swap between the query and the HTTP send is a declared race and is noted in the module header.
