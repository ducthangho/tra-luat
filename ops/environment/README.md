# tra-luat executor/reviewer environment

Both update scripts use `ops/cong_cu.yaml` and `ops/cong_cu.py` for the shared baseline: git, Python, PyYAML, jsonschema, actionlint, shellcheck, ripgrep and Bash. Linux system mode and Windows probe each baseline entry and invoke `ops/cai_cong_cu.sh` only for entries that are not `DAT`, with ShellCheck prepared before actionlint. Linux system mode bootstraps checker PyYAML only when its import is missing, handles nonzero probe exits without aborting repair under `set -e`, and requires each repaired tool to report `DAT` in the parent process. Linux actionlint installation uses child-scoped `AL_DICH=$HOME/.local/bin`; that directory is already on the parent's PATH, so it does not depend on the installer's temporary default or child PATH changes. Linux `--user-only` installs pinned Python dependencies in an isolated venv and runs the same checker. `actionlint` is intentionally pinned to 1.7.7 by the repository manifest; the canary checks its ShellCheck integration. `--latest`/`-Latest` upgrades only the tools named in `--tools`/`-Tools` (default `claude,codex,agy,nlm,gws`); a tool already at the target version is not reinstalled. System tools use the configured OS package manager, so "latest" for those means the newest version in that repository, not necessarily the upstream release. Python and Node major updates can affect existing environments and are never selected by default.

Run the scripts without `--apply`/`-Apply` to inspect. Check mode installs nothing and exits with the checker's exit code. The apply mode refuses to proceed while related tool/runtime processes are active (Claude, Codex, AGY, nlm, gws, uv, Node, Python; on Windows also WSL); on Linux it also refuses when `pgrep` is unavailable. An unknown `--tools` entry is rejected before any installation. `--persist-path`/`-PersistPath` is opt-in and adds user CLI directories idempotently: on Windows it edits the raw `HKCU\Environment\Path` value so existing `%VAR%` entries are preserved; on Linux it appends one marked, POSIX-compatible block to `~/.profile` and `~/.bashrc` that also sets `NPM_CONFIG_PREFIX=$HOME/.local` (do not use it together with nvm). Reopen terminals after changing persistent PATH.

The updater reports only whether `TL_MASTER_KEY`, `TL_SECRETS_FILEID`, `TL_AGENT_CREDS_FILEID`, `TL_WEBAPP`, `TL_TOKEN` and `TL_PROFILE` have nonempty values. It never prints values, generates keys, copies credentials between Windows and WSL, runs `secrets-stage`, or runs `tl bootstrap`. The tra-luat config load order is environment `TL_WEBAPP`/`TL_TOKEN`, explicit `--config`, `~/.tra_luat_config.json`, then `/tmp/tra_luat_config.json`. WSL has its own HOME and must be bootstrapped separately with the repository's documented secret flow once the operator has securely supplied its key.

Windows requires an existing PowerShell 7, Git for Windows (including Bash/cygpath) and callable Python with pip/venv support. From that baseline, plain `-Apply` installs missing gh and Node LTS (including npm) through existing Chocolatey, then missing uv in `%LOCALAPPDATA%\tra-luat-tools\venv`, Claude/Codex/gws from the official npm packages into `%APPDATA%\npm`, and nlm with uv's PyPI package `notebooklm-mcp-cli`. Supplemental CLIs with a successful nonempty version probe are retained; baseline entries already `DAT` are retained. Missing tools are installed regardless of `-Tools`; that list selects upgrades only. Chocolatey operations require an already elevated PowerShell and stop with an explicit prerequisite error otherwise; the updater neither installs a package manager nor opens an elevation prompt. An existing Node with missing/broken npm must be repaired separately, so installing npm cannot silently replace that Node major.

Windows resolves Git Bash beside `git.exe` before either check or apply, and promotes its bin directory on the process PATH so the shared checker cannot select the WSL Bash launcher. Check mode makes only this process PATH adjustment; it does not write persistent PATH. After apply reconciles tool directories, Git Bash is promoted again. Missing actionlint is installed into `%USERPROFILE%\.local\bin` instead of the shared installer's temporary default, then checked in the PowerShell parent; the temporary `AL_DICH` override is restored after installation.

Windows `-Apply` reconciles known user bin, WinGet Links, Chocolatey bin, Node, gh, npm, managed venv and AGY directories into its own process PATH after installs and before final checks. A repaired baseline candidate is accepted only after the shared checker reports that exact tool `DAT` in the parent process; this also handles a stale executable earlier on PATH. No child PATH receipt or installer stdout is imported. This session reconciliation does not require `-PersistPath`; it lasts for the updater process. The login script also recognizes the managed venv Scripts directory. Custom npm/uv install directories must already be on the caller's PATH; unsupported layouts or shadowing cause an explicit failure rather than importing arbitrary paths.

On Ubuntu/WSL, `--user-only` never calls sudo or apt. It checks its prerequisites before any change and requires preinstalled git, python3, python3-venv (`ensurepip`), Bash, ripgrep, ShellCheck, actionlint and PowerShell; use system mode (which needs root or passwordless `sudo -n`) for a minimal Ubuntu installation. System mode supports Ubuntu only. For root, a function exported only to the shared installer's child process translates exactly `sudo apt-get ...` into `apt-get ...`; root does not need a sudo binary, and other sudo commands are refused by that adapter. Non-root system mode uses existing passwordless sudo. In `--user-only` mode, missing native Node (latest LTS) and gh are installed user-local from the official archives with SHA256 verification; system mode uses apt packages. If native Node already exists but native npm is missing or its `npm --version` probe fails, user-only mode stops before installation and identifies the Node path: repair npm through that installation's package manager and rerun. It does not install a second Node or silently change the Node major. The npm probe is also required after a managed Node install. CLIs that resolve to Windows binaries under `/mnt/*` (including Windows AGY) are treated as missing and may receive native Linux installs.

AGY is the `google-antigravity/antigravity-cli` project; its CLI states that it is not an officially supported Google product. Both updaters install missing AGY and upgrade selected AGY from the latest GitHub release API only after requiring and verifying the asset's `sha256:` digest; neither invokes `agy update`. Windows selects `agy_cli_windows_x64.zip` or `agy_cli_windows_arm64.zip` using native OS architecture, accepts exactly one regular root `antigravity.exe` entry, checks its version, then atomically replaces `%LOCALAPPDATA%\agy\bin\agy.exe` using a staged file on the same volume. Unexpected layouts (including extra entries, paths and links), missing/invalid digests, hash mismatches and unsupported architectures fail closed. Installation paths containing reparse points are refused. Linux retains its single-root `antigravity` tar layout check and user bin installation. Both parse a single bare, `version:`, `agy` or `antigravity` semantic version line, allowing unrelated banner lines, and skip download/install when the resolved CLI already reports the release version. If an existing native AGY needs an update or has an unreadable version, only the managed destination (`$HOME/.local/bin/agy` on Linux, `%LOCALAPPDATA%\agy\bin\agy.exe` on Windows) may be replaced. An AGY resolved elsewhere causes a failure before download/install, with its path and guidance to upgrade that installation through its package manager or remove it before a managed install; no second user-local AGY is installed. An existing native AGY at the latest version remains a no-op at any path. After installation they verify version and PATH resolution. GitHub API access is required even for this latest-version comparison; the published digest provides integrity, not an independent publisher signature. Windows persistent PATH remains opt-in with `-PersistPath`.

Do not use the legacy `tl-setup.ps1` to create plaintext `COWORK-paste.txt` as part of generic updates. The updater does not read or change secret values.

## Dùng trực tiếp từ repository

Từ thư mục gốc của `tra-luat`:

```powershell
pwsh -File ops/environment/update-windows.ps1 -Repo .
pwsh -File ops/environment/update-windows.ps1 -Repo . -Apply -PersistPath
pwsh -File ops/environment/update-windows.ps1 -Repo . -Apply -Latest -Tools claude,codex,agy,nlm,gws
. ./ops/environment/login-windows.ps1
python scripts/tl.py doctor --offline
```

```bash
bash ops/environment/update-linux.sh --repo .
bash ops/environment/update-linux.sh --repo . --apply --user-only --persist-path
bash ops/environment/update-linux.sh --repo . --apply --user-only --latest --tools claude,codex,agy,nlm,gws
source ops/environment/login-linux.sh
python scripts/tl.py doctor --offline
```

Trên Ubuntu tối giản, bỏ `--user-only` và chạy với root hoặc `sudo` không cần mật khẩu (`sudo -n`). `--user-only` không bao giờ gọi sudo/apt và dừng trước mọi thay đổi nếu thiếu tiền điều kiện. Chạy chế độ kiểm tra trước, chỉ dùng `--apply` khi các công việc đang dùng CLI đã kết thúc.

### Nạp PATH mỗi lần mở shell (opt-in)

Script login không tự sửa profile. Muốn nạp mỗi lần mở shell thì tự thêm một dòng, thay đường dẫn theo checkout.

PowerShell — thêm vào `$PROFILE`:

```powershell
Add-Content -LiteralPath $PROFILE -Value ". 'D:\Quốc hội\tra-luat\ops\environment\login-windows.ps1'"
```

Bash/WSL — thêm vào `~/.bashrc` (script cần Bash, đừng đặt vào `~/.profile` vì profile đó có thể chạy dưới `sh`):

```bash
printf '%s\n' "source '/mnt/d/Quốc hội/tra-luat/ops/environment/login-linux.sh'" >> ~/.bashrc
```

Các script login chỉ thêm các thư mục CLI người dùng đang có vào PATH của phiên hiện tại, đặt `TL_REPO` và in lệnh kiểm tra; nạp nhiều lần không nhân đôi PATH. Chúng không cài phần mềm, không sửa profile, không đăng nhập và không đọc/lưu `TL_MASTER_KEY`. Sau khi nạp, chạy `python scripts/tl.py doctor --offline` trong thư mục repo. Nếu cần khởi tạo xác thực, dùng quy trình `python scripts/tl.py bootstrap --env code` của repo bằng biến `TL_*` được cung cấp an toàn trong phiên hiện tại; không lưu `TL_MASTER_KEY` vào profile.
