### Finding mới

**R9-1 · P2 — N2 cho phép đăng ký trùng ID làm câu lệnh base chụp nhầm hàm lúc nạp module.** Chèn ngay trước `_r26_original_accept1174 = dict(CASES)["wp1174_writer_accept"]` ở `.claude/dev/packet_loop_test.py:16217`:

```python
def _wp1342a1_noop(c): pass
CASES += [("wp1174_writer_accept", _wp1342a1_noop)]
```

Khối có tên mới đúng tiền tố, dùng đúng mẫu đăng ký và đạt `1111`. Khi nạp blob trong RAM, `_r26_original_accept1174` trỏ tới hàm `case` trên base và trỏ tới `_wp1342a1_noop` sau khi chèn. Thân `_r26_accept1174` giữ nguyên từng byte nhưng từ đó bỏ qua lời gọi ca gốc. Runner base có kiểm đếm trùng cho ID bắt buộc khi chạy suite. Phản chứng này xác nhận riêng vế bất biến N2 đã xanh sai ngay lúc nạp.

Yêu cầu N2 kiểm mỗi mục `CASES += [...]` có ID mới, duy nhất và rời tập ID base. Khóa vị trí đăng ký sau các câu lệnh base đọc hoặc biến đổi `CASES` lúc nạp, trước khối `if __name__ == "__main__"`. Dùng khối trên làm phản chứng đỏ và giữ khối mẫu có ID mới làm đối chứng xanh.
