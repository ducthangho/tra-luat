## 2. Thay đổi

### 2.1 Module mới và quan hệ với C1a1a

Tạo `.claude/dev/doc_receipt_thu_hoi_git.py`. Nó nạp module C1a1a bằng **đường dẫn tệp** cùng thư mục

Hàm thuần (trừ việc gọi git qua reader §2.3):

```
kiem_git(raw: bytes, *, kho, nhanh, base_hien_hanh, head_hien_hanh, master, goc_kho, ngan_sach=None, _seam=None) -> dict
```

`ngan_sach` và `_seam` là API nội bộ cho ca test (thu nhỏ ngân sách, tiêm trôi ref), **không** có cờ CLI.

CLI: `kiem-git --receipt <tệp> --kho <owner/repo> --nhanh-mac-dinh <tên> --base-hien-hanh <oid> --head-hien-hanh <oid>
--master <oid> --goc-kho <đường>`. Không có cờ nào khác; không có cờ đổi MOC.

### 2.3 Reader object và luật phân loại

Module tự đọc object, **không** dùng `git rev-list`, `merge-base`, `rev-parse <x>:<path>` hay `ls-tree` để quyết
định luật:

1. Mọi tiến trình git chạy với môi trường đã lọc: bỏ mọi biến `GIT_*` thừa kế; đặt `GIT_NO_REPLACE_OBJECTS=1`,
   `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=<os.devnull>`, `GIT_TERMINAL_PROMPT=0`; thêm cờ `--no-replace-objects`.
2. Object đọc qua **một** tiến trình `git cat-file --batch`. Mỗi object được **băm lại** (`sha1(type SP size NUL
   body)`) và so với OID đã hỏi; lệch ⇒ `khong_do_duoc`. Dòng `missing` ⇒ `khong_do_duoc`. Kiểu object khác kiểu
   mong đợi ⇒ `khong_do_duoc` cho object hỏi theo cạnh của đồ thị (parent, tree của commit).
3. Parent và tree của commit lấy từ bytes đã băm; entry của tree (mode, tên, OID) parse từ bytes nhị phân đã băm.
   Mode hợp lệ: `100644 100755 120000 160000 40000`; mode khác hoặc entry cụt ⇒ `khong_do_duoc`.
4. Vì vậy `refs/replace/*`, `info/grafts`, commit-graph và alternates **không** đổi được kết luận: chúng chỉ đổi nơi
   chứa bytes, còn bytes phải băm ra đúng OID.

**Luật phân loại (đóng lớp `phan-loai-vang-va-khong-do-duoc`):** một luật ra `khong_do_duoc` khi và chỉ khi thiếu
bytes đã xác minh mà luật ấy cần: object vắng, object băm lệch, kiểu object sai, tree/commit hỏng, vượt ngân sách
§2.6, trôi ref (G9), hoặc tiến trình git chết. Mọi kết luận rút từ bytes đã xác minh, kể cả "entry không có trong
tree", là `qua` hoặc `do`.

### 2.5 Tham số và N6

Trước mọi luật (rc 2 khi sai, stdout rỗng):

- `--kho`, `--nhanh-mac-dinh` khác rỗng; `--nhanh-mac-dinh` khớp `^[A-Za-z0-9._-]+$`, không bắt đầu bằng `-`, và
  `git check-ref-format refs/heads/<nhanh>` rc 0.
- `--base-hien-hanh`, `--head-hien-hanh`, `--master` là hex thường 40 ký tự.
- `--goc-kho` là kho git (`git -C <goc> rev-parse --git-dir` rc 0).
- **N6 ban đầu:** đọc `refs/remotes/origin/<nhanh>` bằng `git for-each-ref --format=%(objectname)` khớp **đúng**
  tên ref (không DWIM). Không đúng một dòng hex40, hoặc khác `--master` ⇒ rc 2. Đây là lỗi của caller hoặc của kho
