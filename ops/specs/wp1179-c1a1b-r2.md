### 2.2 Đầu ra (ABI) và mã thoát

Đầu ra là **một dòng JSON** trên stdout với **đúng bốn** khoá. Byte stdout của CLI phải **bằng đúng**

trả cho cùng đầu vào; không có byte nào khác trên stdout:

| khoá | kiểu | nghĩa |

| `json` | `dict` hoặc `null` | kết quả `kiem_json` của C1a1a, **nguyên vẹn** (cùng ba khoá `ok`/`luat`/`ly_do`). `null` khi và chỉ khi `G0` là `do` |

### 2.3 Reader object và luật phân loại

Module tự đọc object, **không** dùng `git rev-list`, `merge-base`, `rev-parse <x>:<path>` hay `ls-tree` để quyết
định luật:

1. Mọi tiến trình git chạy với môi trường đã lọc: bỏ mọi biến `GIT_*` thừa kế; đặt `GIT_NO_REPLACE_OBJECTS=1`,
   `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=<os.devnull>`, `GIT_TERMINAL_PROMPT=0`; thêm cờ `--no-replace-objects`.
2. Object đọc qua **một** tiến trình `git cat-file --batch`. Mỗi object được **băm lại** (`sha1(type SP size NUL
   body)`) và so với OID đã hỏi; lệch ⇒ `khong_do_duoc`. Dòng `missing` ⇒ `khong_do_duoc`. Kiểu object khác kiểu
   mong đợi ⇒ `khong_do_duoc` cho object hỏi theo cạnh của đồ thị (parent, tree của commit).
3. Parent và tree của commit lấy từ bytes đã băm; entry của tree (mode, tên, OID) parse từ bytes nhị phân đã băm.
   Mode hợp lệ: `100644 100755 120000 160000 40000`; mode khác hoặc entry cụt ⇒ `khong_do_duoc`.
4. Vì vậy `refs/replace/*`, `info/grafts`, commit-graph và alternates **không** đổi được kết luận: chúng chỉ đổi nơi
   chứa bytes, còn bytes phải băm ra đúng OID.

**Bảng đóng phân loại (r2, thay câu văn của r1).** Tập sự kiện `E`, mỗi sự kiện có tên, phát ra **chỉ** tại reader
hoặc tại lần đọc ref:

| sự kiện `E` | phát ra khi |
|---|---|
| `E_vang` | `cat-file --batch` trả dòng `<oid> missing` cho một OID luật cần đọc |
| `E_bam_lech` | bytes nhận được băm ra OID khác OID đã hỏi |
| `E_kieu_sai` | object đọc theo cạnh parent/tree/entry có kiểu khác kiểu mong đợi |
| `E_hong` | commit thiếu dòng `tree`, dòng `parent` sai dạng, tree có entry cụt, mode ngoài tập §2.3 mục 3, tên entry trùng hoặc không phải UTF-8 |
| `E_ngan_sach` | vượt một giới hạn §2.6 |
| `E_git_chet` | tiến trình `cat-file` thoát, đóng ống, hoặc framing (dòng đầu) không đúng dạng `<oid> <type> <size>` |
| `E_troi_ref` | lần đọc ref cuối (G9) khác `--master`, hoặc ref vắng |

Luật cho **mọi** G1–G9: nếu trong lúc đánh giá luật ấy có **bất kỳ** sự kiện `E` nào trên một object luật ấy cần
(cột "đọc" dưới), luật ra `khong_do_duoc`. Nếu không có sự kiện nào, luật ra `qua` hoặc `do` theo cột "kết quả".
Không có đường thứ ba. Một sự kiện trên object mà luật **không** cần thì **không** đổi màu luật ấy.
